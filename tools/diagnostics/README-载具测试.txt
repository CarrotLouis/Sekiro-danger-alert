Sekiro danger alert 1.1.0-dev.3 — 堡垒坦克预警排查

这是采集包，原自动预警规则不变，尚未宣称载具问题已修复。只用一份警报/采集包，替换旧版后完整重启。
依赖 Bingus Shared Loader v18+ 和 ModOptionsMenu v1.2（API 3）。先单人即可，不必找朋友。

目标
同一个原有招式，在徒步时能预警，在堡垒驾驶/炮手位却不预警。需要分别确认：
1. 游戏是否仍能解析本人潜兵、座位与当前载具。
2. 敌人锁定的实体是本人、当前载具、另一个单位，还是只有目标位置。
3. 已通过识别的预警是否启动了声音与图标；本人头部在该视角下能否投影，是否实际提交了图标。
不因身边有坦克就认定坦克属于本人；座位不确定时保留“不可用”。

选敌人
选一个你在徒步时已确认能弹危的原有招式。推荐自然加农炮台，或用放怪工具生成湮灭坦克。
采集分组选“机器人”，招式选“加农炮台 · 炮击准备”或“湮灭坦克 · 炮击”。
五个场景始终使用同一种敌人、同一种招式；先保持距离和视线大致相同。
不使用尚未接入新预警的霸王虫、喷涌虫或冲锋来验证载具缺报。

每个场景单独一份记录，每份最多2分钟/8 MiB。步骤：
1. 先站到该场景需要的位置，或先坐进对应座位。
2. 采集页“采集场景”选对应的“载具排查”项，“操作”选开始采集，APPLY 后关菜单。
3. 若要检查图标，保持采集运行，再将操作选“3秒后预览图标和声音”，APPLY 后立即关菜单。
   3秒后观察有无危字、有无声音。预览不重启记录，也不证明敌人出招识别成功。
4. 诱导相同敌人实际攻击约3次；看到蓄力/准备攻击时按F8，允许反应延迟。
5. 停止采集并APPLY，再换下一个场景；无需同一份记录中反复上下车。

按以下顺序：
A. 载具排查：本人徒步。站在坦克外，先确认原本能弹危；做一次预览，再记约3次攻击。
B. 载具排查：堡垒驾驶位。先正常坐进驾驶位，做一次预览，再记约3次相同攻击。
C. 载具排查：堡垒炮手位。先正常坐进炮手位，做一次预览，再记约3次相同攻击。
D. 载具排查：FRV驾驶位。如有FRV再做，确认你印象里的开车有效是否可复现。
E. 载具排查：空车对照（本人车外）。从堡垒下车后离开车体一段距离，别挡在炮线前。
   若敌人继续明显攻击空车，按F8。若它始终改为攻击本人，说明没有取得空车锁定对照，不要把它算成有效空车攻击。
   此项用于避免后续修复把空车、队友车辆或已下车的旧载具也误当作本人。

如果某一步无法诱导到攻击，先交已有数据并说明即可，不必硬做。
若A徒步基线都不弹危，先告诉我；它不能用于判断坦克独有的问题。
如果使用了座位切换mod，第一轮尽量正常上/下车；有差异再补一小轮用快捷键换座，不必先卸载其他mod。
请简单记下B/C/D预览时“有无图标/有无声音”，以及实际攻击有无预警。日志只能证明提交状态，不能代替人的观察。

读取和风险边界
仅这些手动选择的载具场景才增加只读观测，采用既有版本门控与新增指令字节校验。
记录潜兵ID、实际座位行、座位集合的载具ID、敌人目标ID、网络ID、可选目标描述及头部投影。
转座、离车、所有权变化或身份不一致均明确记录，不拿最近车辆补齐。
没有游戏内存写入、座位切换、敌人生成或新引擎函数调用。没有改变原警报的锁定谓词。
离线检查验证读取和记录逻辑，不证明实机坦克已能预警。数据回来后再按实际目标关系修复，并验证离车后不会继续误报。
