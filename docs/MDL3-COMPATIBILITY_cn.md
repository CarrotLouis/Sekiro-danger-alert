# MDL3 兼容性研究

[English](https://github.com/CarrotLouis/Sekiro-danger-alert/blob/main/docs/MDL3-COMPATIBILITY.md) / 简体中文

首次核对日期为 2026-11-01，分别于 2026-11-03 和 2026-11-06 复查了 dev.33 和 dev.43。Sekiro danger alert 1.0.0 适配 Steam build 25480438。

## 结论

MDL3 dev.43 提供公开的屏幕绘图和音频接口。**攻击识别仍需要 HD2 Data Hub 0.6.0 缺少的数据**，包括敌方招式及进度、房主读取的实际目标或客机收到的同步目标，以及攻击转移目标和取消时的更新。头顶跟随也还需要受支持的头部位置和投影接口。

可行路线是请 Data Hub 补充相关观测，或由 MDL3 作者明确授权一个只读原生模块。本研究没有修改加载器、授权机制、反作弊或游戏内存，也没有生成新的预警包。

## dev.43 和 Data Hub 0.6.0 复查（2026-11-06）

用户提供的 `MDL3-3.0.0-dev.43-preview-Data-Hub-0.6.0.zip` 的 SHA-256 为 `f2bfe300b166471344ade74c06482cc6d5ae88eef7a216dedd8cbf44c9c03f0c`。ZIP CRC 检查通过，实际的 DLL 和加载器补丁哈希与 `BUILD.json` 一致。新版 Hub Lua 主体的 SHA-256 为 `d8d074a1f1e1076800f1827180a96190f4deb08ebea3e2a4adb6e5d0d0b1f970`。原生桥接 DLL 与 dev.33 逐字节相同（原生宿主 0.4.5），Hub 仍通过签名清单和受信任的原生 owner 启动。

与 0.3.0 相比，Hub 0.6.0 增加 `enemy_pool`、`buffs`、`lobby`、`lobby_search` 和 `backpacks` 五个公开函数。现在共有 23 个函数，事件名称仍是原来的 16 个。字段文档、公开接口表和原生分发入口对新增数据范围的描述一致。

| 接口 | 包内实现提供的数据 |
|---|---|
| `HD2Data.enemy_pool()` | 预测任务可能加载的实体类型。没有正在场上的敌人实例或攻击状态。 |
| `entity_damaged`、`entity_died` | 新增攻击者或击杀者的实体身份。伤害事件在观测到血量下降后，从最近一次伤害归属记录读取该字段，无法在这次命中前发出预警。 |
| `HD2Data.lobby()` | 大厅数据可用时提供 `host_is_local` 和成员角色。公开接口对房主和客机都没有提供敌人当前的攻击目标或同步目标。 |
| `HD2Data.strikes()` 和 `aim()` | 打击读取和本地瞄准读取与 0.3.0 相同，分别覆盖特定打击机制和本地玩家的瞄准数据。 |

随包绘图文档说明了 `MDL3.gui` API 1。画布可以在指定屏幕坐标绘制已打包的图片帧，为动画提供受支持的绘制方式。该接口没有世界坐标转屏幕坐标的功能，`HD2Data.player().position` 也是化身的根节点位置。头顶跟随还需要核实头部坐标和投影的来源。文档还说明移动图片会重建画布，跟随动画的帧开销需实机测量。

随包音频文档说明了 `MDL3.audio` API 2。现有 48 kHz 双声道 PCM16 提示音符合文档的格式要求，命名空间音量接口可用于独立的音量滑块。已认可的动画和音效素材可以复用，图片部署、显示效果和声音播放仍需实机核对。[作者的 dev.43 更新说明](https://ayakamods.com/mods/mdl3-preview-%E9%BA%A6%E5%BD%93%E5%8A%B33-%E9%A2%84%E8%A7%88%E7%89%88%EF%BC%81.5710/update/8864/)

迁移仍以房主和客机均可获取命中前的敌方招式和目标为前提。本次已离线核对封包、Hub 实现及绘图和音频文档。当前游戏中的预警时机、头顶跟随及联机行为仍待实机验证。

用户提供的 `MDL3-3.0.0-dev.33-preview-Data-Hub-0.3.0.zip` 的 SHA-256 为 `da60ebd6f96e890516c156992703cf8c7afc826d5ac234f56ce09ab173e5dda4`。ZIP CRC 检查通过，声明的原生 DLL 和加载器补丁哈希均与封包内实际字节一致。与 dev.21 整包直接比较的结果如下：

| 组件 | dev.33 核对结果 | 与 dev.21 相同的 SHA-256 |
|---|---|---|
| 完整 Data Hub 插件归档 | 逐字节相同；Hub 0.3.0、API 1 | `b9f5f0899d519825e903b191fd4829c302f83c8060b2679a0c72965c4385458b` |
| 原生桥接 DLL | 逐字节相同；原生宿主 0.4.5 | `99877159a6914fb4d5dc5efb0d3a12f87c56d75949c119800ebf08de3e61c08d` |
| 包内字段文档 | 逐字节相同 | `820b011ce3102bb58be5cb611d911377c2254a0df88784c9096b2f944ad06a90` |

Hub 仍然只有下文说明的 18 个公开函数和 16 个事件，没有增加敌方 Ability / 攻击计时、选定攻击目标、攻击取消或准备状态观测。因此，现有的命中前、仅对本人目标预警的规则仍然无法恢复。伤害和爆炸事件对于这一用途仍然太晚。

加载器启动补丁发生了变化，其 Lua 头部标明 dev.33、PUC Lua 5.1 和受保护的预览版。本次没有去混淆或执行该启动脚本。下文对加载器授权流程的详细说明来自可读的 dev.21 源码。dev.33 中未改变的 Hub 仍然加载签名清单并开启受信任的原生 owner，原生 DLL 也没有改变。随包公开文档没有提供可供我们自行实现攻击读取器的新受支持接口。

[官方更新记录](https://ayakamods.com/mods/mdl3-preview-%E9%BA%A6%E5%BD%93%E5%8A%B33-%E9%A2%84%E8%A7%88%E7%89%88%EF%BC%81.5710/updates)主要涉及安装、兼容性、音频和崩溃修复。判断攻击数据仍受阻的依据是未改变的 Hub 及其实际 API，而非仅凭更新说明。只升级加载器仍不足以恢复预警；根据这次证据，不制作新的预警包，也不要求补充手动记录。

## 加载器如何运作

启动补丁运行于游戏的 **PUC Lua 5.1** 虚拟机。MDL3 发现插件声明，并提供 `CowboyBingusModLoader`、`ModOptionsMenu`、`ModBindingsMenu` 等兼容全局表，管理各模组的回调与生命周期。

MDL3 将原生桥接组件载入进程，由另一个 LuaJIT 环境执行获授权的原生模块，通过带类型的请求和结果连接两个虚拟机。普通插件被加载，不等于它在游戏虚拟机里获得了 LuaJIT FFI。

Data Hub 使用获授权的原生 owner，读取绑定游戏版本的数据链，通过 `HD2Data` 返回普通 Lua 快照和事件。数据按需读取：例如 `D.player()` 会续期三秒租约，第一次调用可能返回 nil，消费者必须处理数据年龄、任务切换和 Hub 重载。没有功能请求或订阅时，Hub 以 4 Hz 跟踪任务状态。

公共音频服务也采用这条路线：模组调用 `MDL3.audio`，系统音频对象由已授权的音频模块持有。已有 Stingray GUI 绘制仍在游戏虚拟机内完成；旧代码中的原生指针假设不会因为有桥接器就自动兼容。

## 旧版为什么失效

| 依赖部分 | 旧版实现 | MDL3 迁移要求 |
|---|---|---|
| 脚本环境 | `src/native.lua` 在模块加载时就要求 `ffi`；音频与内存辅助模块也使用 FFI | 将游戏虚拟机逻辑与已授权的数据提供者分开，插件内不直接使用 FFI |
| 版本核验 | 固定旧版 `25480438` 的主程序、`game.dll` 文件哈希和指令校验 | 使用已核实的新版本数据提供者，不能删除旧保护来强行读取 |
| 攻击观测 | 原生 Ability 槽、进度与速度，Behavior / Aiming 目标，移动工厂准备状态及同步数据 | 公共 Hub 缺少这些内容，这是主要阻碍 |
| 预警规则 | `src/detector.lua` 同时验证攻击窗口与本人目标，再去重并处理取消 | 新观测与招式映射核实后，大部分纯 Lua 规则可以复用 |
| 菜单 | MOM API `1`、版本 `3`，滑块、选择和开关 | MDL3 提供此兼容协议，保留 `peril_warning.crusher.` 选项标识 |
| 菜单语言 | `BingusTranslations` 注册表 | 需要核实 MDL3 的语言衔接与全部游戏语言，菜单 API 兼容不等于本地化已完成 |
| 声音 | 通过 FFI 调用 WinMM 播放 PCM16 | 改用 `MDL3.audio`，所附服务同时支持 PCM16 与 MS-ADPCM |
| 图像 | 50 组已编译图像与材质，原生资源就绪检查、UI world 查找和头部 / 镜头投影 | 复用已认可的素材，替换或重新核实依赖旧原生数据的就绪与头部锚点路径 |

动画和原始声音不需要重新制作。当前 48 kHz、双声道 PCM16 音效符合音频服务的格式检查，因此不强制改成 ADPCM，但仍需正确的格式头、base64 上传、就绪检查、音量控制和 namespace 清理。这里确认的是离线格式兼容，没有声称已在游戏内成功播放。

## Data Hub 实际提供了什么

已将原始 0.3.0 字段文档与包内公共 API、原生分发入口交叉核对。该版公开函数覆盖本人 / 小队信息、本人的瞄准、战略配备与目录、进行中的打击、任务状态、订阅和诊断。0.6.0 的新增接口见上文 dev.43 复查。

它的 16 个事件名称如下：

```text
mission_started, mission_ended, entity_spawned, entity_damaged,
entity_died, entity_killed, player_fired, player_hit,
player_damage_dealt, player_kill_credited, explosion, bughole_destroyed,
stratagem_called, stratagem_used, strike_started, strike_ended
```

与本模组直接相关的几个区别：

- `D.aim()` 描述的是**本地玩家自己的瞄准**，其中 `target` 是位置，不是敌人选中的受击者。
- Entity 句柄提供身份、阵营、缓存的生命值上限和可选的事件发生时位置，没有当前 Ability 或 AI 目标。伤害事件另带受伤后的当前生命值，但没有任意实体当前生命值的查询方法。
- `D.strikes()` 对应文档中的齐射、飞鹰、轨道等机制，不是所有敌人近战、光束、炮击与冲锋的事件流。
- 伤害、死亡与爆炸观测无法提供命中前的攻击状态，不能满足让玩家提前飞扑的预警要求。
- 目录中出现 `ability` 或 `behavior` 字符串，不等于有实时攻击接口。这些词也出现在静态爆炸名称目录中。

已适配的 BFV 模组展示了适合它自身用途的迁移：从 `HD2Data` 订阅伤害、击杀和统计事件，再通过 `MDL3.audio` 播放声音。它没有恢复敌人的攻击前索敌状态，直接照搬这层事件适配无法恢复 Sekiro danger alert 的行为。

## 为什么不能直接增加私有读取模块

可读的 dev.21 加载器中 `PREVIEW` 为 true。FFI 门面没有实际可用的 FFI 操作，不支持的调用会抛出 `E_UNTRUSTED`；源码提交与模块载入受原生信任检查约束。已有的音频和 Hub 模块通过签名清单绑定源码哈希及允许调用的导出函数。当前版本的比对范围见上文 dev.33 复查。

因此，有 `client`、owner 或模块定义方法，不代表我们自己的代码获得了执行授权。修改已信任模块的内容也会改变源码哈希。本研究没有移除检查、借用其他作者的授权，或将内部原生辅助方法当作公开插件接口。

## 给数据提供者作者的接口需求

以下是针对 Hub 0.6.0 仍缺少的攻击观测**建议的数据协议**。经过过滤的快照或等价的攻击前事件流均可，但必须包含取消攻击与转移目标的更新。

| 所需信息 | 用途 |
|---|---|
| 版本 / 配置身份、任务 epoch、采样时间与数据年龄 | 拒绝不支持或过期的数据，在任务 / Hub 重启后清理旧状态 |
| 本地化身的实体、Unit 与网络身份 | 匹配受击者，避免把实体 ID 与网络 ID 混为一谈 |
| 攻击者的实体、Unit、类型 / 资源、网络身份、存活及所有权 | 选用正确招式规则，拒绝复用实体，并区分权威与同步状态 |
| 当前 Ability / 招式 ID 与槽位、实例 token、已进行时间、速度与暂停状态 | 识别新攻击，在伤害前安排提示，去重变体与连击，取消停滞计时 |
| 当前攻击目标、是否为实体目标、相应网络目标与数据来源 | 只对实际锁定本人的攻击预警，区分房主 Behavior 与已核实的客机同步信息 |
| 相关 Behavior / 攻击阶段、准备状态及其新鲜度 | 支持移动工厂等提示来源不同于普通 Ability 槽的招式 |
| 位置与冲锋进行状态 | 恢复计划中的首次进入指定范围冲锋规则，避免仅凭靠近猜测 |
| 可选的所乘载具身份及座位生命周期 | 继续尚未解决的堡垒问题，避免将任意附近载具误作本人 |
| 可选的头部锚点 / 相机投影 / UI world 支持 | 如果受支持的引擎 API 无法安全提供这些数据，用于替换绑定旧版本的显示读取 |

第一步必须先实现某一种普通敌人的**攻击状态加正确目标**，并覆盖房主与客机。只返回附近敌人或只返回锁定标记都不够；只有已开火 / 已受伤事件则已经晚于本模组需要的时机。

可转给 MDL3 / Data Hub 作者的简短需求：

> Sekiro danger alert 需要只读的、命中前的敌方攻击观测。希望 HD2Data 提供当前 Ability / 招式 ID、实例与进度 / 速度、选定目标的实体 / 网络 ID 及房客机数据来源、相关 Behavior / 准备状态，并附任务 epoch 与数据年龄，同时更新取消攻击和转移目标。目前的伤害 / 击杀 / 爆炸事件无法做到命中前预警。我们可以适配识别器及公共音频、菜单接口，希望采用受支持的 Hub 接口，或经明确授权的只读模块。

## 迁移与验证顺序

1. 先确定受支持的数据接口，或取得只读模块的明确授权。重新核实当前版本数据链与招式含义；旧采集中的 ID 仅作为线索，不能当作新版证据。
2. 实现有预算限制的观测适配层。延迟获取 Hub，处理 nil / 数据年龄 / epoch 及提供者替换，区分权威与同步索敌证据，继续在证据不足时停止预警。
3. 接回现有识别器、设置与已认可素材。将 WinMM 改为公共音频接口，适配语言、头部跟随和资源生命周期，保留 GUID、资源路径、保存标识、延迟与取消规则。
4. 增加 PUC Lua 5.1 检查，并执行识别器与夹具回归。覆盖过期数据、转移目标、重生、死亡、提供者重载、重复攻击、停止 / 重载清理及不支持版本。
5. 实机验证伤害前预警时机：攻击本人或队友、房主或客机、只亮灯后取消，以及各个支持招式。独立验证动画 / 声音与载具视角，测量实战帧开销后再给出性能结论。

现阶段不要求补充手动 F8 采集，前提是先有受支持的观测路径。能够实际读取攻击与目标状态以后，新采集才有意义。

## 本次验证范围

已完成的离线工作包括：检查封包与资源、核对插件身份和公共 API、检查预览版授权路径、核对 PCM 格式、比较当前 Steam 清单，以及确认原有 1.0.0 ZIP 未被修改。本机已有日志也显示 MDL3 以 Lua 5.1、原生宿主 0.4.5 和 signed trust 启动，但这些日志不能证明我们的模组有效。
