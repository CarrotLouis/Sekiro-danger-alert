# 0.8.2 / Enemy Spawner 0.3.1：客机共用读取修复

## 这轮采集实际保存了什么

核对用户本机 2026-10-15 晚间的 9 份 0.8.1 Diagnostics 文件。文件范围含粉碎者、巨型者、强化纵步者、湮灭坦克及几份铁幕坦克选择。

- 9 份都能完整解析，均正常写入 `capture_stop`，没有文件损坏证据。
- 每份在 **0.74–0.84 秒**内触发 8 次 `targeting count invalid` 后自动停止，总计 **72 条读取错误**。
- **0 条 `research_sample`、0 条 `detector_sample`、0 条 `user_attack_mark`**。日志中的 `samples=8` 是采样尝试次数，不能当成八帧有效数据。
- 只保留了少量敌人选中事件，足以证明在本机找到相应资源，不能证明其使用哪招、对谁攻击或触发时机。因采集先停止，用户之后延迟按键和同刻多敌攻击都没有录进去。
- 本体日志在北京时间 19:22:36 起报告 `replicated target counts invalid`，19:23:00 停用自动预警。不是靠这些文件就能确认“客机没有攻击状态”，而是在检查锁定表时提前失败。

因此本轮不创建伪装为真实客机攻击的回放，也不据 F8 猜招。原始文件与本地 JSON 审计报告保留在日志目录 / 忽略的 outputs，不提交 Git。

## 共用索敌表读反

同一构建的 Aiming 管理器 `game+0x3326D30`：

| 偏移 | 正确含义 | 原生证据 |
| --- | --- | --- |
| `+0x140` | 全部记录数 | `game+0x6BC3FD: mov ecx,[rbx+0x140]`，后续用于轮转范围 |
| `+0x144` | 本机负责处理的前缀数 | `game+0x6BBE15: mov eax,[rbx+0x144]`，限制权威更新段 |

0.8.1 将两者解释成相反顺序，校验了错误的大小关系。房主上两者常相等，客机上总数大于本机前缀，导致正常表被拒绝。原来客机合成测试也使用了相反的布局，因此不能说明旧版支持了真实客机。

0.8.2 由生产 `aiming_header()` 唯一解释这两个数，诊断 `targeting_header()` 复用它；限制仍为 `0 <= owned_prefix <= total <= 4096`。实体索引上界使用 total，不能使用 owned prefix 截断远端记录。错误消息额外写出两个数便于诊断；保留 pin / 目标身份 / 暂存网络 ID / 位置目标 / 死亡与换潜兵校验，没有放松锁定本人条件。

两个读取位置的 6 字节指令分别加入生产 / 诊断读取 pin，与本机保留 build 25480438 的代码一致。没有新增 native 调用、内存写入、距离猜测或从旧 AI 缓存推断锁定。

## 生成工具的独立故障

0.3.0 `0ded0eb3646a` 在两次运行中均记录：

```text
bad argument #2 to 'read_memory' (cannot convert 'number' to 'const void *')
```

三次后关闭可选联机通道。`channel.lua` 把 lobby 名称、SDK 返回字符串及分页游标转为数字后，直接传给 Bingus reader；实际 reader 不会替调用者转换 `ReadProcessMemory` 的指针参数。旧测试的 mock 自动转换数字，掩盖了问题。

0.3.1 在通道唯一读取入口显式 `ffi.cast('const void *', address)`。保留两端安装、当前房主执行、成员绑定、白名单、nonce / 去重、发布限流、资源加载和穿刺虫难度条件。没有改成客机本地创建。现在还会显示 lobby 不就绪、房主未公布工具状态等等待原因。

回归测试要求真实指针类型，修复前能复现失败。另使用实际 vendored Bingus reader 对**测试进程自己的 Lua 缓冲区**检查：数字地址抛同类 FFI 错误，转换后的指针正确读出内容。没有打开运行中的游戏或调用其 SDK；这不是联机成功的证据。

## 采集不再被一个可选通道拖停

Combat 采集的索敌表头与逐敌 aim 观察均为可选通道。若失败，研究帧保留能力、武器、其他已成功的同步状态，并在 `targeting_table.error` / `observation_errors` 写原因；F8 保持有效。必须的场景 / 当前潜兵 / Health 读取失败仍计错并在八次后停止，读取与耗时上限不变。

研究帧增加 `targeting_table.total / owned_prefix`。停止记录和设置说明增加 `successful_samples`、`marker_count`、停止原因；采样尝试计数 `samples` 保留兼容旧分析。有效样本指成功写出的观察帧，不等于识别出的攻击次数。正常包仍不包含采集和 F8。

## 验证与下一步

离线已验证：

- 修复前，原客机测试改成正确 `total=1 / prefix=0` 后复现计数错误；指针严格化的通道测试复现地址类型错误。修复后通过。
- `total=2 / prefix=1` 的远端尾部记录可被生产目标读取和诊断发现 / 解析；超限 / 反序的计数仍拒绝。
- 实际生产 target / Ability / Health 读取与 Detector 联合的 **41 个资源 / 能力组合**，加既有 Factory 同步准备测试，覆盖 20 个招式设置；持续多轮不因计数关系错误停用，攻击别人时仍不提示。
- 原有 7,241 条房主匿名攻击输入及 313 条炮塔输入、猎杀器延迟、真实 MOM 菜单、R2 素材与封包检查继续使用原测试。没有改动这些攻击窗口或设置默认值。
- 可选 aim 故障下连续采集 12 帧并保存两次 F8；必须通道故障时停止并明确报告零有效样本；真实 MOM 描述能显示计数和停止原因。
- 生成工具保留双端请求 / ACK、去重、换任务与死亡取消、主机权威与资源门禁的原测试；新增严格指针及真实 reader 边界检查。

**这证明修复了两个可复现的实现错误，不能证明真实客机的每种攻击都及时弹危，或 PlayFab 请求已完成跨端传递。**本轮没有新的有效客机攻击样本，也没有实机运行候选包。

优先给双方更新生成工具 0.3.1，客机使用 0.8.2 Diagnostics，完整重启。先任选巨型者劈砍或强化纵步者火箭验证一次公共链路，确认设置中的有效样本数增长、F8 次数增长，再测几次攻击。当前无需重新寻找全部敌人逐一采集；若仍缺特定同步事件，再根据新帧决定最小补测范围。

GUID、入口、既有保存 ID 与用户外观 / 延迟选项不变。仅本地构建测试 ZIP，不发布 Release 或上传 outputs。
