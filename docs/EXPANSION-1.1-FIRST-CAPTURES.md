## 原生时序和周期

沿用已验证的 Ability 时钟 60 tick/s。当前代码的派发入口是 `0x115c784 + 4*(id-1)`，记录的是 image RVA；不可错误地再加一次跳表 RVA。

| Ability | 处理入口 RVA | 静态事件与本次样本 |
|---|---|---|
| 188 | `0x10a6300` | 第 55 tick 请求第一武器槽开火，第 110 tick 停止；观测到的开火输入起点约 0.92–0.99s |
| 187 | `0x10a60a0` | 第 135 tick 请求开火，第 200 tick 停止；观测到的完整起点约 2.26–2.36s |
| 222 | `0x10a85d0` | 第 80 tick 进入接触攻击段；之后可能转到 223 刹停或 225 撞击 |
| 464 | `0x10b92c0` | 第 80 tick 使用对应接触段；之前有准备，之后可转到 465 或 468 |

开火输入不是独立测量的命中；接触段启用也不是玩家实际受伤帧。表中的原生事件用于约束候选规则，不构成最终闪避时间已通过实战验证的结论。钻地喷涌虫 186 的出土/抛射流程没有同样的武器输入边沿，不应仅因相邻 ID 一起纳入持续吐酸。

本次还发现钻地喷涌虫一次持续的 187 从一个密集数组槽搬到另一个槽，时钟与实体连续。分析器现在按资源、实体生命周期、Ability 及连续时钟识别周期；槽号改变不新建周期、不重复记录开火边沿。原分析中的历史 `ability_runs` 仍保留，新增 `expansion` 通道只统计活动状态，排除停在表里的非活动缓存行。

后续接入仍需校验当前生命周期、活动标志、暂停/时钟和实际本人目标。`222 → 223/225` 或 `464 → 465/468` 是同次冲锋的结束，不因阶段切换重新允许提示。准备、死亡、撞击和冷却不能冒充新冲锋；原有跺脚及其他预警窗口保持不变。

0 分别关闭对应组的距离预警；已在同次冲锋触发后不重复，改变范围不制造入圈事件。配置与纯状态机已更新，正式设置注册与原生适配将在其余新招式整合时一起接入。菜单规划为 26 个招式开关、两个范围和重置共 29 行，音画另为 8 行。

距离目前是潜兵与敌人根坐标之间的三维距离，不是碰撞表面距离。阿尔法四段 464 中，三个持续到可观测接触段，最短距离分别约 5.93、5.86、12.60m；另一段在接触段前已进入撞击。按当前 5m 阈值，这份阿尔法数据不会产生前冲入圈提示，不能因此判断事件识别失败。范围上限按要求扩到 15m，默认仍为 5m，等待用户分别实测。

## Gazer 核心生成候选 0.4.1

此前只知道两种结构没有 `EnemyPackageComponentData`。本次进一步解析本机 slim 安装的 DSAR/DSAA 索引、公共 archive 内 3631 项 package 目录，并交叉验证 `bundle_database.data`，找到包含其真实 unit、动画、状态机和材质的原生场景包：

| 核心 | 根实体与 Unit | Behavior | 原生 package | 目录项数 |
|---|---|---:|---|---:|
| Gazer 小炮台 | `0883366204e1ccc5` | 305 | `6ed3d770b520924d` | 47 |
| Gazer Spire 激光塔 | `1448d494665d01a0` | 306 | `d48566d2a4e10857` | 189 |

两项 package 资源都位于公共 archive `9ba626afa44a3aa3`；package 记录是 16 字节头与逐项的 type/name 两个 u64。两者均明确包含对应的 `unit` 类型 `e0a48d0be9a7453f`，不把“相似路径”当作依赖。目录 SHA-256、unit 对应、三种组件字节门禁保存在[生成工具配置](../tools/enemy_spawner/config/enemies.json)。

实现仍调用原先核对过的通用实体创建入口和包引用请求，无新增原生函数、ABI、内存写入或钩子。创建前要求 EnemyPackage 缺失、Behavior 与 Unit 身份吻合、炮座/传感器/激光组件与静态数据逐字节一致、package 所有 part 与模型就绪；创建返回后仍检查 Health、Unit、本机拥有、Behavior 和初始目标。不匹配就停止继续生成。

它们加入独立生成工具的新增列表，索引 23/24；前 22 项及协议索引保持不变。**新两项仅支持单人光能任务**，客机请求、多人或玩家状态未知均拒绝，准备资源后又有人加入也取消。原有 22 项继续沿用联机生成流程。原因是这些结构缺少移动敌人的生成包组件，目前没有验证客机如何取得它们的资源，不能用房主加载成功代替。

这是武器核心，不是完整任务场地、塔基、营地或传送门。其普通任务中的外观、索敌、开火及光束挂点仍需实机确认；离线资源存在不能证明原生 AI 不依赖其他场景条件。先在开阔平地各生成一只，确认这些行为后，再用现有 1.1.0-dev.1 Diagnostics 的 Gazer / Gazer Spire 范围采集即可，无需等待对应任务开放。若没有行为或创建验证失败，反馈工具日志，勿把“选项可选”当作生成成功。

场景包格式参照 [FileDiver package reader](https://github.com/xypwn/filediver/blob/6bf7c1ccc4be465a35b4bc9d41087781b47034e6/stingray/package/package.go) 与本地同版本 slim reader。实体/类型库仍使用[准备记录](EXPANSION-1.1-PREPARATION.md)列出的同一镜像指纹。
