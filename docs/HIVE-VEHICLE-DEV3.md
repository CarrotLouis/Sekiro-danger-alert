## 采集器调整

旧版预算计时覆盖采样、JSON 编码、flush 和可选动画，因此仅凭停止原因不能确定是原生读取、GC、编码还是磁盘延迟耗时。本版不把未测量的原因写成已确认根因。

原 AI 十六进制缓冲曾在每个 combat 样本重复生成，现仅在约每秒一次的 heartbeat 样本生成；每次的结构化 AI、Ability、目标与输入状态仍保留。原始数据的缺席在其他样本是有意限频，不能解释为对应组件不可用。

每个采集/预警快照记录通道独立计算预算。一次超过 20 ms 会记录通道、耗时、连续次数，采样降至至多 5 Hz 约一秒；恢复正常则清除该通道的连续计数。连续三次超预算，或一次达到 50 ms，仍立即结束。八次必需读取失败、每步 2500 次读取/1 MiB、时长、分段和总量上限继续有效。没有提高读取次数或扩大扫描范围。

霸王虫仍最多 60 分钟、每五分钟/8 MiB 分段、总计 256 MiB/64 段，同任务增援按新 epoch 继续。`-` 只标出土下压，`=` 只标破土拍击；`[` 或 `]` 均可标吐酸，分析统一按最终控制项合并。历史内部子项标识保持兼容，不把它们当作已核实的吐酸变体。

## 堡垒问题与可证实的边界

用户报告：单人、堡垒驾驶及炮手位均不预警，记忆中 FRV 驾驶时可能有效。当前源码只允许敌人的实体目标等于本地潜兵 ID；客机还要求处理后的实体/网络 ID 一致。源码能证明**当前没有载具目标别名**，不能证明本次游戏实际锁定的必然是堡垒。另一个独立可能是潜兵头部在载具相机中不可投影，导致实际已触发的动画被隐藏。此次霸王虫文件没有载具观测，不能据此确诊坦克。

`config/vehicle_probe.json` 固定 Steam build 25480438、同一 game.dll 哈希和四段指令校验；使用当前离线 SeatCollection 组件所有者交叉确认七种载具资源。安装的 Vehicle Specified Seat Switch 仅提供查找线索；读者重新按保留模块段核对 seater 全局、哈希头、64 字节行、集合 ID/节点和 100 字节 collection 行。没有复制该模组实现，没有调用其函数或加载其 Native helper。

新增 `tools/diagnostics/src/vehicle.lua` 只在手动选定的载具场景采样：

- 观察玩家 avatar 槽及解析出的资源、实体、Unit、网络 ID；槽内容意外时保留原值，不将 Unit 与实体 ID 混同。
- 用当前潜兵的 seater 行连接实际 SeatCollection 所有者；记录节点、过渡/活动标志、所有权和可选位置。身份、行、头或集合变化则明确不可用，不采用最近车辆推定。
- 独立记录敌人的 AI、Aiming/同步目标及能通过现有 Health 表核对的目标描述。本人潜兵、当前座位集合和其他实体保持不同关系，不能凭资源名将任意堡垒当作本人。
- 使用已有头部投影和 GUI 分辨率接口记录能否投影。诊断入口记录自动/手动预览的声音请求结果、音量、图标启动及 bitmap 提交状态。手动预览不被算成自动识别。
- 旧潜兵门控若取不到 avatar，仍以低频记录玩家槽的独立可用信息；不继续敌人读取或补造本人身份。分析器明确这类文件缺少独立攻击样本。

模块没有修改任何生产锁定谓词或游戏内存；没有新引擎函数调用。只增加本地观测与明确触发的原有图标/声音预览。原设置页不变，采集页仍七行；原两种场景索引保持，追加五种载具场景；原操作索引保持，追加三秒后预览。保存值不会在加载时自动开始或预览。

## 实机最小对照

完整步骤在 [同包载具说明](../tools/diagnostics/README-载具测试.txt)。固定一个徒步时已能稳定预警的原有攻击，推荐加农炮台或湮灭坦克炮击。按徒步 → 堡垒驾驶 → 堡垒炮手各约三次，并分别做一次延后预览；有 FRV 再做 FRV 驾驶。最后尽量取得空车被攻击的负对照；如果敌人始终转为攻击本人，注明未取得该对照即可。

每阶段先进入座位，再选相应场景并开始，F8 标攻击，结束后换阶段；每段仍为 120 秒/8 MiB。记录车辆场景文件和普通日志，同时由用户说明预览/真实攻击时有无图标及声音。初轮单人足够；不能据此承诺房主/客机和队友车辆全部覆盖。

后续修复必须从实际记录选择分支：若锁定当前乘坐载具，则仅接受已核对座位生命周期的当前实体/网络身份；若仅投影失败，则修复载具显示锚点而不扩大锁定条件。离车、空车、队友车辆、转座中、复活后的旧载具和失效同步目标均需拒绝。未有证据之前不按目标位置相近推定锁定本人。
