# 0.7.0 客机路径与验证边界

版本继续使用 0.x.x，GUID `1dc82965-3c84-4eec-bb72-88e8121ac0dc`、入口 `mods/peril_warning/crusher_probe`、全部保留设置 ID 不变。粉碎者只改显示名称，仍使用 `peril_warning.crusher.move.crusher_melee`。

## 已知实测与此次修正

用户报告上一包作为客机测试移动工厂炮击、巨型者劈砍，均没有预警；其他敌人未测试。这不是“所有客机招式均已验证失效”的采集证据。此前有效攻击回放来自单人 / 房主。

旧检测器直接拒绝 `owned=false` 的敌人，因此即使读取到有效攻击，也不可能为常见客机敌人预警。旧能力读取还把 manager+8 的总实例数当作容量、只扫描 manager+12 的原生更新前缀。此次扫描全部实例，在固定预算内继续轮转；不能据此断言所有前缀外记录都会在客机推进时钟。

房主继续信任本机拥有的有效 AI 实体目标。客机不使用缓存 AI，也不把单独一个瞄准实体 ID 当作当前目标。

## 原生布局证据

保持 Steam build 25480438。game.dll SHA-256 `2E2C3B7C2500646DADD5F2B4C6E0504DBB7E7896139F64CDDC0D1813C718F51E`，exe SHA-256 `F5FEE03DCFDB2E553A4752C283590950AC13316B376D8196AA556FF0400D5F06`。新增 21 段指令在本地保留模块中逐字节核对，进入读取前仍需整模块版本检查及相关指令检查。校验点见 [peer_sync.json](../config/peer_sync.json)。

- Ability manager `game+0x3326640`：`0x54A212` 读取 +8 总数；`0x54A332` / `0x54A33A` 分别增加 +12 更新前缀与 +8 总数。原生每帧更新 `0x7C8887` / `0x7C94F7` 仅遍历 +12。读取全部实例不会自行驱动攻击时钟，模组不写内存。
- Aiming manager `game+0x3326D30`：+0x140 前缀 / +0x144 总数；map +0x150，实体句柄数组 +0x168，0xD0 记录数组 +0x178，0x18 网络记录数组 +0x180。`0x6BC343..0x6BC3ED` 遍历同步尾部；网络目标转实体后写入 aim[0]，已处理网络目标写入 aim[4]。
- 客机目标要求网络目标非 `0x7FFF`、非 position-only、与 aim[4] 一致、aim[0] 为本机潜兵实体、网络目标等于本次潜兵 descriptor+0x10 的网络 ID。再次核对表头、句柄、记录和实体身份；加入、增援、替换、销毁或中途改变均不继承旧身份。
- Behavior manager `game+0x3326740` 的 map / handles 与原读取一致；+0x68 是 stride 0xA0 的网络状态数组。`0x844C3B..0x844C7C` 把 full Behavior 的阶段与类型写入 network+0 / +4；`0x845927..0x84592E` 把 full+0x1E8 标志写入 network+0x78。
- 接收路径 `0x845C33..0x845C3B` 定位该网络数组，`0x845C94` / `0x845CB2` / `0x845E63` 分别写入收到的阶段、类型和标志。模组直接读接收结果，不调用解码器。
- 移动工厂 `0x1C3AAE..0x1C3AB7` 在准备位 bit 28 变化时提交 dirty mask 0x40000；`0x1C2674..0x1C2697` 在入口清除并同步准备位。因此可观察接收到的阶段 3、类型 99 与准备位，但不能把房主 full+0x188 的 AI 时间当作客机有效计时。

## 客机判定

常规招式继续使用原有精确资源 / 能力白名单、预警窗口、暂停 / speed / 最短提前量与招式开关。只有同一能力时钟实际推进后，才允许同步目标路径触发；不自行猜测动画起点或推进计时。目标同步缺失、位置目标、攻击别人、旧潜兵、没有活动能力、计时停滞或已经错过窗口时保持安静。

移动工厂使用接收到的准备信号由未就绪变为就绪的变化，并要求阶段 3 / 类型 99 / 同步目标为本人。第一次看到就绪状态仅作基线，不补发旧预警；连续观察间隔不得超过 0.35 秒。准备与目标包相邻到达时最多等待 0.2 秒；一旦目标确认属于别人，之后转向本人不借用该轮准备信号。每轮只提示一次。房主继续使用已有原生准备时间的 0.5–0.8 秒窗口。

两个读取源的原生语义不同，因此客机工厂提示时刻是“收到新准备信号”，不能声称与房主 0.5 秒窗口完全相同；这需要实测。提前信号仍可能在之后取消而不开炮。

## 离线检查证明的内容

- 安装游戏的真实 LuaJIT 编译实际封包，真实 ModOptionsMenu API 3 注册单页 25 项、18 个招式开关；中文名称、保留保存值、全部重置与旧功能移除通过。
- 合成内存覆盖同步尾部选取、已处理网络 ID / 实体 / 当前潜兵身份的一致性、位置模式、换人 / 增援、句柄替换、无效计数、销毁 / 所有权变化及指令不符拒绝；Behavior 接收数组独立读取，不依赖缓存 AI。
- 合成客机轮询覆盖巨型者时钟停滞 / 推进、同轮去重、重复攻击、别人目标 / 缺失目标 / 缓存 AI 拒绝；工厂覆盖初始已亮灯、准备信号多轮切换、目标包顺序、后续转向、扫描中断、超时、开关关闭及拒绝房主时钟来源。
- 生产原生读取器与检测器在合成内存中整链联测：巨型者 Ability → 同步目标 → canonical 健康 → 提示，及工厂世界描述符 → Behavior 网络准备 → 同步目标 → canonical 健康 → 提示；缺少 full AI 记录仍工作，死亡对象拒绝，两条路径都在读取预算内。
- 原有 6,169 条扩展招式与 313 条炮塔真实样本回放继续通过。它们保留原本房主语义，没有把 `owned` 改成 false 来伪装为客机采集。
- 主安装包仍没有采集 / F8 / 武器输入诊断 / 逐次攻击转储，不新增 FFI 声明或调用，不写游戏内存。能力每批最多 2048 行 / 32 个匹配，工厂每批最多 8 个，合用 2500 次 / 1 MiB 读取预算。

## 仍需真实联机确认

本轮未运行真实联机，未取得客机攻击采集。离线通过不证明实际网络一定发送所有招式所需的数据，也不证明巨型者客机能力计时一定推进或飞扑窗口足够。

优先由客机测试巨型者劈砍、移动工厂炮击：攻击本人时出现危，攻击另一名潜兵时不出现；继续观察同一敌人多轮攻击及增援后是否恢复。随后再扩展其他已支持招式与房主回归。

日常 `Sekiro danger alert.log` 每 30 秒最多一行 `observation` 汇总：能力总数、原生更新前缀数、本批客机敌人数和客机判定原因计数。它不保存玩家 ID、原始地址、原始内存或逐次事件。若仍失效，可先据此区分未见攻击、同步目标不可用、计时未确认和错过窗口，再决定是否需要专门采集。
