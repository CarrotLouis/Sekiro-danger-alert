## 静态时序证据

从留存的当前版本解包代码段重新解码。参考共享布局来自 [HD2Runtime 75988a9](https://github.com/SkyeShade/HD2Runtime/tree/75988a992141023e50fc0193f4b1de017d9e4b57)；本表中的能力处理分支独立核对。

| RVA / 路径 | 含义 |
| --- | --- |
| `0x11509E0`，表 `0x115C784 + (id-1)*4` | 能力 ID 分派；1037 对应表项 `0x115D7B4`，进入 `0x1154E09 -> 0x10D6780` |
| `0x7C88C9`、常量 `0x23C7740` | 能力时钟乘以 60，再按跨越的整数 tick 调用分派 |
| `0x10D6789`：tick 60 | 准备分支：状态操作、武器准备调用，并发送效果 `0x4B9563C2` 和音频事件 `0x41F40E92` |
| `0x10D67C7`：tick 90 | 调用 `0x11B9B60`，在武器状态中设置触发输入并同步；作为原生扳机时点 |
| `0x10D67DB`：tick 130 | 另一个效果 / 音频事件；不作为预警点 |
| `0x10D67FB`：tick 150 | 复位相关状态并返回能力完成，匹配约 2.5 秒的采集周期 |

据此在能力计时 **1.0 秒**准备分支附近预警，正常速度的扳机输入在 **1.5 秒**。准备事件与用户描述的闪光相符；没有同步录像，不能声称已测出屏幕闪光的准确首帧，扳机输入也不等于测到了弹丸出膛 / 命中。

新读法额外核对 `config/attack_probe.json` 的 12 处字节 / 常量；行为读取核对 `config/targeting_probe.json` 的 20 处字节。模块文件哈希和代码布局不匹配时拒绝使用。这里只读取；上述原生函数均不由模组调用。

## 实现规则

- 普通重炮塔资源 + 能力 1037 + 计时 `[1.0, 1.2]`，且按速度计算距扳机输入至少 0.2 秒。超过窗口不补响。
- Crusher 资源 + 既有 13 个非脚部攻击分支 + 计时 `[0, 0.35]`；1409 / 1410 / 1423 跺脚明确排除。
- 两者都要求当前描述符由本机拥有、对应 AI 记录身份一致、`has_target` 为真、实体跟踪位有效、目标 ID 等于当前本机潜兵。AI 指向坐标、目标缺失 / 其他潜兵或未经验证的非本机所有权均不提示。
- 没有距离条件。没有将武器瞄准遗留值作为 AI 缺失时的回退。
- 每个攻击周期只提示一次；计时重置重新武装。短缺帧、分批扫描和槽位移动由身份、周期和短冷却抑制重复。同一批多名攻击者分别记事件，音画合并播放一次。
- Crusher 使用通用行为管理器的相同目标布局。新的目标过滤只有静态 / 离线依据，旧 Crusher 日志缺少 AI 目标，不能用其替代新规则的实测。

## 为什么仍有读取预算

旧方法要先找到实体，再读取位置才能计算距离；“只观测附近”并不能省掉所有发现 / 位置读取。0.3.2 已修复远处对象长期占据前 16 个名额，用户确认超过 16 只的场景正常。

0.4.0 改为先扫能力表，只对匹配资源的相关攻击读取目标；不读取敌人位置来决定触发。每批最多扫描 2048 条能力记录、匹配 32 条相关攻击；超出时保存下一条游标，不永久淘汰后面的敌人。原生总读取保护仍是每批最多 2500 次 / 1 MiB，能力表最大 8192 条。**这些是每次执行预算，不是敌人总数上限，也不是距离上限。**

32 个攻击匹配预算也可能被仍在进行的攻击占用，但下一批接着后面的记录，已经提示的攻击不会一直抢占扫描起点。极端密集攻击、表布局变化或低帧率仍可能错过窄窗口；本版不承诺无限数量、固定延迟或零漏报。详细诊断采集仍使用邻近候选选择；其 8 / 16 个对象不参与自动预警决定。

## 离线验证

执行 `python scripts/build.py`，再设置已安装游戏的 `HD2_LUA51_DLL`，运行 `python scripts/test.py --mom-source work/ModOptionsMenu`，最后运行 `python scripts/verify_package.py`。

以上命令全部通过：3 组 Python + 9 组 Lua 检查。成品为 `Sekiro danger alert 0.4.0.zip`，2,135,452 字节；SHA-256 `1392107e34694a5ee20609288ae487ed3e46c2f510aa25c420c5ad68324db8a6`。成品与压缩图像对照仅保存在本机 `outputs/`，不上传仓库。

- 两份采集派生的匿名回放 `tests/fixtures/cannon_targeting_replay.lua` 保留 313 个攻击样本的真实计时、所有权和目标标志。得到 **2 + 8 次**提示，无重复；提示时距离原生扳机事件 **0.422～0.493 秒**。回放没有运行游戏，也没有证明本版端到端画面延迟。
- 缺失 / 错误目标、跺脚、未知资源、暂停、过晚样本、过快能力、计时重置、身份更替和读取错误均有拒绝或重置测试。
- 合成内存验证超过首批 2048 行的攻击会被继续扫到、40 个同时攻击者分两批都被处理、未知资源 / 非法数量 / 指令不匹配被拒绝；证明游标逻辑，不能替代极端实机性能验证。
- 934 条旧 Crusher 能力回放没有目标证据，按新规则全部不触发；另用明确标注的合成目标测试 13 个分支。没有给历史记录伪造锁定信息。
- 使用实际游戏 LuaJIT 做编译、菜单、只读解码及生命周期测试；封包检查资源、GUID、Lua 内容、50 帧 BC1 图像与已确认 R2 素材。
