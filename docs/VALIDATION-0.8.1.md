# 0.8.1 / Enemy Spawner 0.3.0 验证范围

## 猎杀器采集

已读取 2026-10-15 用户本机的两份 0.8.0 单人采集。电击文件有 8 次 F8、673 次研究采样、约 74.75 秒；激光文件有 7 次 F8、661 次研究采样、约 73.67 秒。研究采样间隔中位数约 0.111 秒，最大约 0.147 秒，观察通道没有报告读取错误。第二份以 `restarted` 正常结束，数据可用，不需要为此重采。

标记邻近的电击能力为 **1961**，激光为 **1956 / 1957**，与原生武器槽映射一致。两份连续日志合计记录 15 次电击预警、14 次激光预警；自动记录不限于 F8 标记。**1962 未在本次采集中出现**，继续保留其已核对的原生电击分支，不能声称已实测此变体。未采到攻击队友的对照，也没有客机证据。

抽取 1,072 条最小匿名判定输入作为新回放：只包含相对时间、替换后的实体 / Unit、能力 ID / 计时、所有权和目标布尔量，不提交原始日志、路径、地址、坐标或 F8 原文。与原有 6,169 条展开招式回放合计 7,241 条；原有各招触发数保持不变，新回放复现上述 29 次预警。另有原来的 313 条炮塔回放。

这证明当前本机招式映射和日志可用于调时，不等于测出了真实命中帧。F8 有人工反应延迟，武器输入时刻也不等于伤害命中时刻。

## 预警时机与延迟

现有规则并非所有敌人刚开始动画就提示。近战多数在识别到对应能力的早期窗口提示；穿刺虫、泰坦吐酸、蟑龙俯冲、机器人炮击等使用各自的蓄力 / 准备窗口。移动工厂也有独立的准备状态路径。单纯索敌不触发：仍需锁定本人并进入所选招式窗口。

猎杀器沿用最初的早期窗口作为基准。新增两个稳定保存 ID：

- `peril_warning.crusher.delay.harvester_tesla_ripper`
- `peril_warning.crusher.delay.harvester_disintegration_beamer`

都是秒数滑块，**0–2 秒、步进 0.1 秒、默认 0**。0 保持原时机；音效和图标同一事件触发，延迟相同。分别排在对应招式开关之后。普通页共 29 项，未超过真实 MOM 的 32 项上限；20 个原招式开关及其他旧 ID 不变。

在原本应当提示的那一帧才建立延迟，按本地单调时钟等待，不会因后来才扫到一个旧能力而凭空补发。等待过程中仍重新验证当前能力、计时推进、存活实体、本人目标和潜兵身份。取消 / 切招 / 死亡 / 转向队友 / 观察中断 / 重置时取消；已安排的一次使用当时的延迟，新设置对下一次生效。滑块上限只是实验范围，不会自动把太晚的设置修成最佳飞扑时机；攻击已经结束则不再提示。

离线用实际游戏 LuaJIT 和真实 ModOptionsMenu 检查了两个滑块的范围、步进、持久化、独立值、默认恢复，以及 0 / 0.1 / 0.7 / 2 秒触发、一次性、取消和入口接线。视觉与声音素材保持原 R2。

## 客机生成

Enemy Spawner 0.3.0 允许客机在自己的菜单选择 / APPLY。**房主和客机都必须启用本版生成工具**。房主仍可按原流程直接生成。客机不直接调用实体创建；由当前房主执行既有创建接口。只安装客机一端无法让未装工具的房主响应。

使用游戏已接入的 PlayFab lobby member property 通道，来源为 HD2Runtime `peer_channel.lua` / `windows_write.lua` 的已核对 ABI 与布局。工具独占 `sda_spawn` 键，不使用游戏聊天、不复用 `hd2rt` 等 Runtime 键、不传任意 RPC 或 Lua。无需安装 HD2Runtime；保留 MIT 署名和许可证。

本机保留的 build 25480438 代码重新核对了 70 条通道 pin（含完整两个包装器）和 14 条玩家 / avatar 读取 pin：

- `exe+0x8C6F30`：`const char *(engine_lobby, peer_u64, key)`，完整 223 字节，成员查找后读取 SDK 缓存值。
- `exe+0x8C7010`：`i32(engine_lobby, count_u32, keys**, values**)`，完整 66 字节，向本机自己的 member property 发起一次 SDK 更新。
- 每次调用前检查 joined flag、PlayFab state 3、handle、成员身份、当前 host、注册表 / table / 两个槽和 pin。
- 启动至少 20 秒后工作；通道首次观察到 lobby 后再等 10 秒，并等待游戏自己的 platform post，最长等 20 秒。每 5 秒最多一条 property 更新，不重复发布相同值；三次失败停止该 lobby 的发布。
- 接收值仅限 512 字节 ASCII，按页有界读取。每轮只读最多 1,000 次 / 64 KiB，0.5 秒轮询；耗时超过 10ms 则退到 2 秒，连续三次超过 20ms 停止联机通道，保留房主本地生成。

请求只允许 16 项白名单索引、请求 token、房主当前任务 nonce、请求者 avatar 网络 ID 和归一化的镜头水平朝向。没有资源哈希、地址或世界 XYZ 参数。房主从自己读到的当前玩家列表将发送 peer 绑定到 avatar 网络 ID，再从网络实体表、Health / Unit 取得存活潜兵和当前位置。初始攻击目标也是该请求者。

同一 token 在当前任务只处理一次，重排也不重试；最多保留 128 个 token、三个队友 ACK。任务 / 房主 / 主持潜兵更换后 nonce 失效，闲置 nonce 每 60 秒更新；不将旧 property 当新请求。请求者死亡、增援、退出或不在该任务会取消。资源检查和实际创建前再次验证房主权限、场景、请求者身份、资源和容量。旧有每任务最多 32 次创建、至少 3 秒间隔、资源 90 秒超时及穿刺虫 5–10 难度条件继续有效；客机等 ACK 最长 180 秒。

离线测试覆盖双端请求 / ACK、只由房主创建、精确一次、过期 / 重排 / 错误输入、玩家与网络 avatar 不匹配、死亡 / 换任务取消、host 端落点 / 目标、native 参数 ABI、join 延迟、发布频率、失败限制及 exact wrapper 的实际 FFI 回调边界。

**待实机**：两个延迟的最佳飞扑值、客机请求传递、房主创建后的跨端模型 / AI / 攻击同步、房主迁移和平台服务延迟。单人无法验证这些联机项目。本轮未启动或写入运行中的游戏，也未自动部署；只生成本地测试 ZIP。用户原有猎杀器单人效果反馈与本轮新代码的离线验证分开记录。
