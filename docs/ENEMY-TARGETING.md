# 敌方索敌研究与采集（Steam build 25480438）

2026-10-14。结论：可以读取实体级别的 AI 当前目标和瞄准系统目标，具备实现“只对针对本人的攻击提示”的基础。尚未证明炮塔的哪个阶段等于闪光 / 开火前摇，也未证明客机上的时效性。因此 0.3.2 提供只读采集，机器人自动提示暂不启用。

## 三种状态需要分开

1. **被 AI 选为目标**：候选目标经过选择后写入行为记录。目标会刷新、重选、失效，也可能变成最后见到的坐标。这不等于马上攻击。
2. **瞄准系统正在跟踪本人**：系统接收目标实体或坐标，计算目标点、提前量，再驱动炮塔转向。存在网络目标转换路径，但不能据此宣称客机一定能及时获得可用数据。
3. **具体危险攻击进入前摇**：须按敌人 / 武器确认阶段、计时或事件，并与实际闪光、发射对齐。只有这一步与目标条件结合，才能给出有用的躲避提示。

没有找到可以直接用于所有敌人的通用“已锁定并将在下一刻造成致命伤害”布尔值。HD2Runtime 对哨戒炮的研究也把选择目标、瞄准和扣动扳机分别处理。其哨戒炮的距离、阶段编号及重选周期不能直接移植到敌方炮塔。

建议后续触发条件：**已核对的敌人 / 武器 + 有效实体目标为当前本机潜兵 + 已验证的危险攻击前摇开始 + 每次攻击只提示一次**。机器人不沿用 10 米触发限制；采集范围与观察数量只作为性能预算，不能混同为危险距离。

## 原生证据

来源为 [HD2Runtime 75988a9](https://github.com/SkyeShade/HD2Runtime/tree/75988a992141023e50fc0193f4b1de017d9e4b57)，主要文件：

- [research_custom_payloads.py](https://github.com/SkyeShade/HD2Runtime/blob/75988a992141023e50fc0193f4b1de017d9e4b57/scripts/research_custom_payloads.py)：`pelicanAim`、`TARGETING`。
- [research_pelican.py](https://github.com/SkyeShade/HD2Runtime/blob/75988a992141023e50fc0193f4b1de017d9e4b57/scripts/research_pelican.py)：`targetChoice`、`targetSet`、`aim`、`pelicanWeapon`。
- [research_sentry_components.py](https://github.com/SkyeShade/HD2Runtime/blob/75988a992141023e50fc0193f4b1de017d9e4b57/scripts/research_sentry_components.py)：感知、瞄准、炮塔转动与行为之间的关系。

本地留存模块声明的 game.dll 文件 SHA-256 与当前适配版本相同：`2E2C3B7C2500646DADD5F2B4C6E0504DBB7E7896139F64CDDC0D1813C718F51E`。本轮重新反汇编核对下列关键指令；采集开始时再核验 20 处指令字节，完整列表见 `config/targeting_probe.json`。没有调用这些原生函数，只读取经过边界校验的数据。

| 证据 | 已核对的含义 |
| --- | --- |
| `game+0x3326740`，行为记录步长 `0x1F8` | 每个实体的行为记录；实体映射在 manager `+0x40`，句柄 `+0x58`，记录 `+0x60` |
| `0x6BBF88`、`0x6BBFDD` | 瞄准更新读取行为记录 `+0x78` 的 hasTarget、`+0x18` 的目标实体 |
| `0x6BBFD7`、`0x6BBFE0` | 检查行为记录 `+0x60` 的 bit 0；实体跟踪路径把目标写入瞄准记录 `+0` |
| `0x6BC08E`、`0x6BC0BD` | 另一条路径将 AI 坐标写入网络位置记录；不能把遗留的实体编号当作有效锁定 |
| `game+0x3326D30`，瞄准记录步长 `0xD0` | 数量 `+0x140`，实体映射 `+0x150`，句柄 `+0x168`，记录 `+0x178` |
| 网络数组 `+0x180`，每项 `0x18` | `+0` 网络目标、`+0x10` 标志、`+0x14` 坐标模式；网络目标 `0x7FFF` 表示无目标 |
| `0x6BC3A8`、`0x6BC3CB`、`0x6BC3D2` | 接收路径把网络目标解析为本机实体 ID，写入瞄准记录；证明存在同步路径，不证明延迟上界 |
| 瞄准记录 `+0x08`、`+0x14` | 目标点及加入提前量后的瞄准点；它们不等于实际弹丸轨迹 |
| 行为记录 `+0`、`+8`、`+0xC` | 行为 ID、当前阶段、待切换阶段；阶段编号须按该行为解释，`0xFFFFFFFF` 可表示无待切换阶段 |

另外核对了共享目标设置 / 刷新路径：`0x4AF50A` 复制感知条目、`0x4AF53D` 设置 hasTarget、`0x4AF41C` 清除无效目标、`0x4AF4A2` 更新最后感知时间。原生行为有独立的扳机入口（例如 `0x4BC9C9 -> 0x786BE0`），进一步说明“选择了我”和“这次要开火”需要分别观察。

这些是静态代码证据与离线解码验证；尚不是本模组炮塔实测证据。采集会分别输出 AI 与瞄准结果，缺失 AI 时不会用瞄准数据伪造 AI 状态。还会分别记录收到的网络目标、已解析的网络目标及二者是否一致；`entity_target_valid` 仅检查非坐标模式 / 非无效编号，不代表同步完成或开火条件成立。

## 0.3.2 采集方式

在 MODS > Sekiro danger alert 选择“炮塔索敌采集 / Turret targeting capture”，开始两分钟采集并 APPLY。它和 Crusher 采集互斥，不自动播放机器人危险提示。F8 在此模式下只打标记，不手动播放危字。

先测试一座普通重炮塔，等待它转向、闪光、射击若干次。看见闪光或开火后按 F8 即可，按晚了也能回溯。为了精确测量反应窗口，最好同时录下这段画面；F8 是检索段落用的人工标记，不当作闪光的准确时刻。

建议分次覆盖：

- 本人做房主、炮塔打本人。
- 有队友时，炮塔从本人转向队友或反过来；最好相互拉开，便于分辨目标。
- 进入掩体后失去视线、再次出现；检查目标保留与坐标模式。
- 作为客机重复，确认是否仍能读取瞄准目标及攻击前摇，延迟是否足够小。

不必为采集刻意承受炮击。日志名为 `Sekiro danger alert-Targeting-日期-时间.jsonl`，位于 `%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs`。记录本机潜兵实体 / 单位、炮塔类别 / 距离 / ownership、AI 目标 / 阶段、瞄准目标 / 坐标模式、瞄准点、能力计时、实际采样间隔及读取错误。F8 同时保存最近观察及其年龄；不会把旧样本当作按键瞬间的状态。

采集只观察目录中十类原生机器人炮塔资源，包含重炮、坦克炮塔、指挥地堡炮塔等候选；类别对应原生资源名，不把它们全部宣称为已确认的游戏俗名。最多持续观察 8 个已发现的近处候选，范围上限 2000 米，每次发现最多 128 个组件条目、检查最多 16 个新候选。新目标发现与轮转可能延迟；日志显式记录待处理数量和容量排除。默认 20 Hz，耗时超过 5 ms 后降频，单次超过 20 ms / 累计八次读取错误 / 8 MiB / 两分钟即停止。

离线汇总：

```powershell
python scripts/analyze_capture.py '<日志绝对路径>'
```

输出到忽略的 `outputs/`，包含目标及阶段转换、采样间隔、F8 前 4 秒至后 1 秒的观察窗口。工具不将阶段变化自动命名为开火，也不将无记录解释为没有敌人。

## 何时能启用自动预警

需要先建立炮塔实例 / 武器与行为阶段的映射，再比较目标切换、闪光、发射的时间顺序，测量在本人为目标时立即飞扑的效果。优先选择攻击已经进入稳定前摇、同时仍留有躲避时间的事件。太早的索敌提示可能在炮塔转完前就播放完，太晚的出膛事件又会缩短反应窗口。

“目标为队友”时不提示，会按设计漏掉队友附近的爆炸波及和交叉火线；目标过滤本身也不能保证飞扑成功。玩家与炮口的距离、弹速、爆炸半径、地形和联机延迟仍会影响结果。此阶段先验证普通重炮塔，不把结论自动推广到地堡速射炮、连发火箭、坦克或所有机器人。
