## 猎杀器两种攻击的原生证据

[用户指定 Wiki](https://helldivers.wiki.gg/wiki/Harvester)用于招式名称和近距离电击 / 光束的区分；能力映射依据当前原生代码和实体组件，不把 Wiki 的文字时长直接当作 Ability 计时。

关键事实保存在 [harvester.json](../config/harvester.json)。**挂载数组顺序不等于逻辑武器槽位。** `0x30537D..0x3053C6` 明确按挂载名称调用 `0x4CF440`：

| 逻辑槽位 | 名称 hash / 默认实体 | 实体组件 |
| --- | --- | --- |
| 0 | `20c9e777`（beam） / `c6a5bb8b319217ac` | BeamWeapon，kind 12 |
| 1 | `00af1732` / `8dbf99607bd8e550` | ArcWeapon，kind 1 |
| 2 | `db230c92`（cannon） / `cb85e7f7ff8855f4` | ProjectileWeapon，kind 54 |
| 3 | `eb54ccde` / `e8a244ffa3a48fe4` | BeamWeapon，kind 23 |

- **Tesla Ripper：1961 / 1962。** 处理器 `0x1109A10` / `0x1109B60` 在 tick 0 准备逻辑槽 1，tick 60 / 65 / 70 请求槽 1 的发射输入；对应 ArcWeapon。一次能力只在开始时提示一次，不为三段电弧重复提示。
- **Disintegration Beamer：1956 / 1957。** 处理器 `0x1109180` / `0x1109330` 使用逻辑槽 0，tick 60 开始持有输入；对应 beam。两种处理器共用一个激光开关，实际哪些变体会在本体出现仍须采集核对。
- 1963 使用槽 2，不能因为同在 Tripod 处理器附近就当作电击，显式排除；1966 是生成相关能力，也排除。
- 新增 19 个当前版本校验片段，覆盖六个相关分派 / 处理器和完整名称槽位绑定区段。没有调用这些函数，仅核对并读取状态。

首次测试采用能力时间 0–0.35 秒的开始窗口，继续要求资源、有效本人目标、存活身份和招式开关；客机仍须同步目标与计时推进。以 1 秒作为保守最早输入界限，不把真实光束伤害或飞扑成功率说成已测量。新目录状态为 `enabled_from_native_pending_capture`；原 16 项仍保留 `enabled_from_capture`，没有新增伪装的实机回放。

## 设置与 Diagnostics

普通包共 27 项、20 个开关，按虫族 → 机器人 → 光能族排序，最后三个敌人招式条目为粉碎者 / 猎杀器电击 / 猎杀器激光。组间使用已验证的 gap，不注册额外标题行。GUID、入口及所有原有选项 ID 不变。

普通包没有采集模块和 F8。可选 Diagnostics 包与其 GUID / 入口一致，须替换使用；增加独立六项采集页，按阵营拆成 10 / 7 / 3 个招式下拉，均不超过 MOM 的 16 项上限。警报单页不被采集项挤满。

客机采集必须在客机电脑记录本人被攻击；房主代采朋友不能证明客机读取情况。采集版保留完整本体并记录实际检测快照，同时独立采集选定敌人的活动 / 非活动能力、同步目标、网络 Behavior、原生 AI / 武器状态、动画和 F8 延迟。缓存 AI 不可读时按通道记原因，不丢弃可用网络状态。每次最多 120 秒 / 8 MiB，采样约 10 Hz、按耗时退避，20 ms 单次耗时、2500 次 / 1 MiB 读取约束不变。F8 只在采集中且游戏前台时读取。重开、停止、换场景 / 潜兵、全设置重置均有边界；可选采集失败不停止主警报。

完整分工与步骤见 [采集说明](../tools/diagnostics/README-采集说明.txt)。本轮优先复测巨型者、移动工厂，分别采猎杀器电击 / 激光及攻击队友对照。
